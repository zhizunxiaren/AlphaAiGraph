# AlphaAiGraph UI 设计文档

日期：2026-05-13

## 设计目标

AlphaAiGraph 的界面应表达一个清晰的产品心智：

```text
用户把复杂对象交给 AlphaAiGraph。
AI Agent 先生成研究 workflow 脑图。
Agent 标出重点、难点、风险、推荐下钻点和待验证点。
用户选择研究路径。
证据、旁路提问、并行任务、候选结果和执行结果围绕节点展开。
```

本 UI 设计参考用户提供的多面板研究工作台截图，但不照搬其聊天产品结构。参考图可借鉴的是：

- 左侧对话 / 研究过程流。
- 中间大画布承载节点地图。
- 右侧资料阅读和资源列表。
- 多面板并排工作时的高密度、低装饰、强上下文感。

不能借鉴的是：

- 以聊天作为产品主轴。
- 把脑图做成普通卡片网格。
- 让 PDF / 文件管理压过研究地图。
- 后台结果静默进入主图。

## 设计原则

### 1. 研究地图是主角

第一屏必须让用户立即看见当前研究 workflow 脑图，而不是普通 dashboard、知识卡片列表或聊天窗口。脑图表达“怎么研究这个对象”，而不是“这个对象有哪些知识点”。

### 2. Agent 是研究向导，不是聊天助手

Agent 区域应呈现结构化研究事件流：

- 扫描了哪些资料。
- 生成了哪一层研究地图。
- 为什么标记某个节点为重点、难点、风险或待验证。
- 推荐用户下一步下钻哪里。

Agent 不应显示成大段聊天气泡，也不应让用户感觉自己在和普通问答机器人对话。

### 3. 证据靠近决策

用户选中节点后，相关证据、资料片段、执行结果和候选发现应出现在节点检查器内或资料抽屉内。用户不应为了判断一个节点是否值得下钻，在多个页面之间跳转。

### 4. 并行结果默认隔离

并行任务产出的节点、证据、发现和结论必须先进入候选区。只有用户显式合并后，才进入主研究图。视觉上必须区分：

- 主图节点。
- 候选节点。
- 已合并结果。
- 需要审核或冲突的结果。

### 5. 高密度但冷静

界面应像研究员的工作台：信息密度高、结构清晰、边界克制。避免营销页、装饰卡片、渐变光球、大面积品牌色和空泛 hero。

## 目标布局

推荐采用 **四栏研究驾驶舱 + 可折叠资料抽屉**。

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 顶部上下文栏：项目 / 会话 / 当前研究路径 / 模式切换 / 全局命令              │
├──────────────┬──────────────────┬──────────────────────────┬────────────────┤
│ 研究对象导航 │ Agent 研究过程流  │ Research Workflow Canvas │ 节点检查器     │
│ 220px        │ 340-380px         │ 自适应主画布             │ 400-460px      │
│              │                  │                          │                │
│ 对象         │ 扫描事件          │ 根节点                    │ 节点摘要       │
│ 会话         │ 地图生成事件      │ 第一层节点                │ marker 理由    │
│ 线程         │ 判断理由          │ 选中路径                  │ 证据锚点       │
│ 资料入口     │ 推荐下一步        │ 候选节点投影              │ 动作 / 候选    │
└──────────────┴──────────────────┴──────────────────────────┴────────────────┘
                                  │
                                  └── 可折叠资料抽屉：PDF / 代码 / 文档 / 来源列表
```

### 为什么不是五栏常驻

参考图是五栏并排，但 AlphaAiGraph 的主轴是研究地图。若资料和资源列表常驻占据太多宽度，中间 workflow 会被压缩，主体验会变成“文件阅读器 + 聊天 + 附带脑图”。因此默认保留四栏，资料作为右侧抽屉或节点检查器中的 tab 打开。

## 区域设计

### 1. 顶部上下文栏

职责：提供当前研究位置和全局状态。

内容：

- 产品名：AlphaAiGraph。
- 当前 ResearchObject。
- ResearchSession。
- ResearchThread。
- 当前研究路径 breadcrumb，例如：

```text
AlphaAiGraph / 主研究线程 / 产品定位 / 证据与验证
```

- 画布模式切换：
  - 研究地图。
  - 关系图谱。
- 全局命令：
  - 打开资料抽屉。
  - 查看任务队列。
  - 搜索资料或节点。

设计要求：

- 高度控制在 48-56px。
- 固定在顶部，但不能遮挡内容。
- breadcrumb 是 drill-down 产品的方向感核心，必须常驻可见。

### 2. 研究对象导航

职责：提供稳定的项目方向感，不承担主要操作。

内容：

- 当前研究对象。
- 对象类型：project / repository / pdf / document_set 等。
- 当前会话。
- 当前主线程。
- 资料数量。
- 研究线程列表。
- 资料入口。
- 全局视图入口：
  - 研究地图。
  - 候选结果。
  - 资料。
  - 关系图谱。
  - 输出。

设计要求：

- 宽度约 220px。
- 使用 compact rail 风格，不放长说明。
- 当前区域有清晰 active state。
- 导航项使用 Lucide 图标 + 文本，不使用 emoji。

### 3. Agent 研究过程流

职责：让 Agent 的研究判断可见、可追踪、可行动。

Agent 流不是聊天区，而是研究事件流。每个事件块应使用固定结构：

```text
事件类型
Agent 判断
依据 / rationale
建议动作
关联节点 / 资料 / 任务
```

事件类型包括：

- 资料扫描完成。
- 第一层地图生成。
- 发现重点节点。
- 发现难点节点。
- 发现风险节点。
- 推荐下钻。
- 需要验证。
- 并行任务完成。
- 候选结果待审核。

设计要求：

- 宽度约 340-380px。
- 像研究日志，不像聊天气泡。
- 事件块可折叠，默认展示最近和最相关事件。
- 选中节点后，Agent 流优先显示该节点的 marker 理由。
- warning 和失败任务必须显眼，但不使用刺眼大面积红色。

### 4. Research Workflow Canvas

职责：表达当前研究会话的主 workflow。

画布必须区别于普通卡片网格。推荐布局：

```text
root node
   ├── 产品定位 [重点] [核心入口]
   ├── 研究工作流脑图 [难点]
   ├── 并行研究 [风险]
   ├── 旁路临时会话 [建议下钻]
   ├── 证据与验证 [待验证]
   └── 关系图谱投影 [不确定]
```

视觉表达：

- 根节点位于左侧或中心偏左。
- 第一层节点向右展开。
- 选中路径使用更粗连线或高亮轨迹。
- 节点之间必须有明确边关系。
- 候选节点以虚线边框、灰紫背景、半透明连接线挂在相关节点旁。
- 运行中的节点显示状态点或细进度条。

节点内容：

- 标题。
- 一句摘要。
- marker 中文标签。
- 证据数量。
- 动作数量。
- 候选数量。
- expansion state。

节点状态：

- `open`：普通节点。
- `active`：当前研究路径节点。
- `under_review`：候选或待审核节点。
- `verified`：已验证节点。
- `deferred`：暂缓节点。
- `closed`：已关闭节点。

设计要求：

- 不使用等宽卡片网格替代脑图。
- 不一次性把深层节点全部展开。
- 下钻只展开选中节点的一层。
- 关系图谱只能作为投影视图切换，不作为主图编辑面。

### 5. 节点检查器

职责：围绕当前选中节点做决策。

结构：

```text
节点摘要
  标题 / kind / status / expansion state
  marker badges

Agent 判断理由
  marker rationale
  confidence

证据锚点
  来源文件 / 页码 / 行号 / quote
  打开资料抽屉

建议动作
  深入研究
  创建旁路临时会话
  查看资料
  运行验证

候选结果区
  pending_review
  needs_review
  merged
  conflict reason

并行任务
  queued / running / completed / failed

执行结果
  command
  status
  output summary
```

设计要求：

- 右侧宽度 400-460px。
- 分区标题短，不使用说明性大段文字。
- 主操作只有一个：当前节点可下钻时突出“深入研究”。
- 旁路会话必须标明“默认不写入主图”。
- 候选结果必须标明“合并前不写入主图”。

### 6. 可折叠资料抽屉

职责：显示与当前节点相关的资料、PDF、代码片段和证据来源。

触发方式：

- 顶部“资料”按钮。
- 节点检查器中的证据锚点。
- Agent 事件中的关联资料。

内容：

- 资料列表。
- 当前选中来源。
- PDF / 文档预览。
- 代码行片段。
- 命令输出。
- EvidenceAnchor 高亮。

设计要求：

- 默认关闭，不常驻挤压主画布。
- 打开后从右侧覆盖或推入，宽度 420-560px。
- 关闭后保持当前选中资料状态。
- 资料抽屉不是主导航，不应取代节点检查器。

## 视觉系统

### 设计调性

采用 **冷静、工业化、数据密集的研究工作台**。

关键词：

- dense but readable。
- technical。
- evidence-first。
- analyst cockpit。
- restrained industrial。

避免：

- 营销页 hero。
- 大面积紫蓝渐变。
- 装饰性光球、bokeh、玻璃拟态堆叠。
- 过度圆角。
- 卡片套卡片。
- emoji 作为结构图标。

### 色彩

使用语义 token，不在组件中散落硬编码颜色。

推荐 token：

```text
--color-background: #F4F5F3
--color-surface: #FFFFFF
--color-surface-muted: #F0F2EF
--color-border: #D9DED9
--color-text: #17211F
--color-text-muted: #66736D

--color-primary: #176B5B
--color-primary-soft: #E3F1EC
--color-focus: #176B5B
--color-difficulty: #4F5AA8
--color-risk: #B8544E
--color-validation: #B47A1B
--color-candidate: #7A6A96
--color-running: #2F6FA3
--color-success: #2E7D5B
```

用途：

- 当前路径和 active node：深青绿。
- 重点：深青绿。
- 难点：低饱和靛蓝。
- 风险：低饱和红。
- 待验证：琥珀。
- 候选：灰紫。
- 运行中：数据蓝。

### 字体

推荐使用技术型但可读的字体组合：

- 标题 / 数据标签：Fira Code 或 JetBrains Mono。
- 正文 / UI 文本：Fira Sans 或 IBM Plex Sans。

如果不引入外部字体，使用系统字体作为 fallback，但设计文档以 Fira Code + Fira Sans 为目标。

字号建议：

```text
label: 11-12px
metadata: 12px
body: 13-14px
panel title: 14-16px
canvas node title: 14-15px
top context title: 16px
```

设计要求：

- 面板内不使用 hero 级大字。
- 长文本优先换行，不强行截断。
- locator、command、node id 使用 monospace。

### 间距与边界

推荐 spacing：

```text
4px: 微间距
8px: badge / 元信息间距
12px: 紧凑卡片 padding
16px: 面板内 section gap
20px: 主区 padding
```

边界：

- 面板之间使用 1px border。
- 卡片圆角不超过 8px。
- 节点卡片圆角 6-8px。
- 不使用重阴影；只在浮层和抽屉使用轻阴影。

## Marker 设计

不要在 UI 上直接显示枚举值。

映射：

```text
focus -> 重点
difficulty -> 难点
risk -> 风险
recommended_drilldown -> 建议下钻
needs_validation -> 待验证
low_priority -> 低优先级
uncertain -> 不确定
core_entry -> 核心入口
```

marker badge 需要：

- 中文标签。
- 颜色 + 文本共同表达，不只依赖颜色。
- hover / 展开后显示 rationale 和 confidence。
- 一个节点可同时有多个 marker。

## 候选结果设计

候选结果是并行研究产物，不属于主图。

视觉规则：

- 候选节点用虚线边框。
- 候选连线用虚线或低透明度。
- 候选区固定显示状态：
  - 待审核。
  - 需要复核。
  - 已合并。
  - 已忽略。
- 冲突候选显示 conflict reason。
- 合并按钮必须是显式动作。

文案要求：

```text
候选结果区
合并前不写入主图
```

## 旁路临时会话设计

旁路会话用于解释临时概念，不污染主研究图。

入口：

- 节点检查器中的“旁路提问”。
- 选中文本或概念后的浮动操作。

显示：

- 会话问题。
- context policy：
  - 当前节点。
  - 当前分支。
  - 全项目。
- 状态：
  - open。
  - resolved。
  - discarded。
  - promoted。

必须显示提示：

```text
旁路会话默认不修改主研究图。
只有用户选择沉淀后，才生成概念笔记或研究节点。
```

## 关系图谱视图

关系图谱是长期投影，不是主数据源。

入口：

- 顶部模式切换。
- 左侧导航。

设计要求：

- 标明“由研究数据投影生成”。
- 不展示为默认首页。
- 不允许用户误以为它是当前研究 workflow 的编辑面。
- 返回研究地图入口必须明显。

## 响应式设计

桌面宽屏，推荐四栏：

```text
220px / 360px / minmax(640px, 1fr) / 420px
```

中等屏幕，小于 1280px：

```text
左导航压缩为 rail
Agent 流可折叠
节点检查器保留
资料抽屉覆盖显示
```

窄屏，小于 900px：

```text
顶部上下文栏
主画布
底部 / 右侧 sheet：节点检查器
Agent 流、资料、候选结果改为 tabs
```

移动端原则：

- 不允许横向滚动。
- 主研究地图优先显示当前路径，不强行展示完整图。
- 关键操作触摸目标不小于 44px。
- 底部 sheet 必须可关闭，并保留返回地图的入口。

## 交互动效

动效只用于表达状态和空间关系，不做装饰。

允许：

- 节点选中时 150-220ms 高亮过渡。
- 下钻时子节点淡入 + 轻微位移。
- 资料抽屉 slide-in。
- 候选合并后状态 crossfade。
- 运行中任务使用低调进度条或状态点。

禁止：

- 大面积扫描线。
- 无意义的循环动画。
- 改变 layout 的宽高动画。
- 超过 500ms 的慢动画。

必须支持：

- `prefers-reduced-motion`。
- 动画不阻塞点击。

## 可访问性要求

必须满足：

- 文本对比度至少 4.5:1。
- 图标按钮必须有 aria-label。
- tab 顺序符合视觉顺序。
- 当前选中节点使用 `aria-pressed` 或等价状态。
- 关系图谱和研究地图切换必须可键盘操作。
- 颜色不是唯一信息来源，marker 必须有文字。
- 资料抽屉打开后焦点进入抽屉，关闭后焦点回到触发按钮。
- 错误、warning、任务失败使用可读恢复文案。

## 关键用户流程

### W1：进入研究对象

用户打开项目后应立即看到：

- 当前对象。
- 当前会话。
- 当前主线程。
- 第一层研究地图。
- Agent 生成地图的事件。
- 当前推荐下钻点。

成功标准：

- 不读文档也能知道这是一个 AI 研究地图工具。
- 第一屏不是空白脑图，也不是聊天应用。

### W2：选择节点

用户点击一个研究节点。

界面响应：

- 画布高亮选中节点和路径。
- Agent 流显示该节点相关判断。
- 节点检查器显示 marker、证据、动作。
- 资料抽屉不自动打开，除非用户点击证据。

### W3：深入研究

用户点击“深入研究”。

界面响应：

- 只展开该节点下一层。
- 不展开无关分支。
- 新节点从选中节点方向出现。
- breadcrumb 更新。

### W4：查看证据

用户点击证据锚点。

界面响应：

- 资料抽屉打开。
- 定位到对应 PDF 页、代码行或文档段落。
- 对应 evidence anchor 高亮。

### W5：旁路提问

用户在节点上创建旁路会话。

界面响应：

- 会话显示在节点检查器。
- 主图不变。
- 只有用户选择沉淀，才生成 ConceptNote 或候选节点。

### W6：审核候选结果

并行任务产出候选结果。

界面响应：

- 候选进入候选结果区。
- 主图上可投影候选节点，但以虚线和候选标签显示。
- 用户点击合并后才进入主图。
- 冲突候选必须显示原因。

## 实施验收标准

实现这份 UI 设计时，至少应满足：

- 第一屏是四栏研究驾驶舱，而不是三栏普通 dashboard。
- 研究 workflow 脑图是主画布。
- Agent 研究过程流可见，且不是聊天气泡。
- marker 显示中文产品语言。
- 选中节点后，节点检查器内容同步更新。
- 证据锚点靠近节点决策。
- 资料抽屉可打开和关闭。
- 候选结果与主图视觉隔离。
- 旁路临时会话明确默认不写入主图。
- 关系图谱被标明为投影视图。
- 桌面和窄屏都无横向滚动。
- 所有按钮、图标、状态满足基础可访问性。

## 与当前实现的差异

当前实现存在的问题：

- 三栏结构没有独立 Agent 研究过程流。
- 中间节点是普通网格卡片，不像 workflow。
- 右侧把证据、动作、任务、候选、输出混在一个长列表里。
- marker 显示枚举值，不是产品语言。
- 资料没有形成可折叠抽屉。
- 候选结果隔离感不够强。

目标重构方向：

- `LeftPanel` 收敛为研究对象导航。
- 新增 `AgentFeed` 作为研究过程流。

## 设计来源

本设计综合了：

- 用户提供的多面板研究工作台参考图。
- `frontend-design` 的生产级前端设计要求：明确风格、避免通用 AI 审美、重视字体、空间、动效和细节。
- `ui-ux-pro-max` 的设计系统建议：Data-Dense Dashboard、Drill-Down Analytics、技术型字体组合、可访问性、触控目标、响应式布局、状态清晰度和动效约束。
- AlphaAiGraph 项目产品定义：AI Agent 驱动的渐进式研究 workflow 脑图，而不是普通知识图谱、PDF 总结器、静态脑图或聊天工具。
