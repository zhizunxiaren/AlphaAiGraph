# AlphaAiGraph 研究驾驶舱 UX 设计

日期：2026-05-11

## 意图

AlphaAiGraph 需要从“功能展示型 demo dashboard”改成真正可用的研究驾驶舱。第一屏必须让用户感到：AI 研究 Agent 已经扫描了一个复杂对象，生成了研究地图，识别出重点、难点、风险点，并等待用户选择下一条研究路径。

本设计不照抄任何参考产品。参考图只用于吸收工作台密度、多面板研究流和资料并排分析的方向。

## 产品角色

AlphaAiGraph 是一个 AI Agent 驱动的渐进式研究地图产品。

它不是：

- 通用知识图谱查看器
- PDF 总结器
- 静态脑图
- 学习卡片生成器
- 聊天优先助手

产品界面应该传达：

```text
我把一个复杂对象交给 AlphaAiGraph。
Agent 生成了第一层研究地图。
它标出了重点、难点、风险、推荐下钻点和待验证点。
我选择一个节点。
Agent 只展开这条路径，并把证据、旁路会话、候选结果和执行结果沉淀到研究地图上。
```

### Project 分析助手角色

AlphaAiGraph 可以提供一个独立的 project / 工程分析助手角色。这个角色不是新的产品主轴，而是 AlphaAiGraph 面向 project、代码仓库或工程目录时的一种 Agent 工作模式。

Project 分析助手的职责是帮助用户快速建立工程研究路径：

- 识别项目结构和主要模块
- 找到核心入口文件、配置、服务边界和关键依赖
- 标注复杂、风险高或值得优先阅读的模块
- 提出需要验证的问题，例如构建、测试、接口契约或数据流假设
- 把代码行、文件片段、命令输出和文档段落作为证据锚点
- 生成可下钻的研究节点，而不是一次性分析完整个项目

这个角色仍然使用研究地图、marker、证据、下钻、旁路会话、候选结果和显式验证流程；它不应该退化成普通代码聊天助手。

## UX 原则

1. 研究路径优先。
   主界面表达当前研究 workflow，而不是优先展示关系图谱。

2. Agent 引导必须可见。
   用户应该看见 Agent 为什么把某个节点标记为重点、风险、难点或推荐下钻。

3. 证据必须靠近决策。
   证据锚点、资料来源和执行结果应该出现在选中节点旁边，而不是被放到割裂的导出区域。

4. 后台工作不能静默改写主图。
   并行分析的输出先进入候选结果区，只有用户审核或合并后才进入主研究地图。

5. 旁路提问默认隔离。
   临时概念问题不能修改主研究地图，除非用户明确沉淀或提升。

6. 高密度但冷静。
   UI 应该像分析师工作台：紧凑、可读、克制、方便扫读。

## 第一屏信息架构

第一屏使用四区研究驾驶舱。

### 1. Project Rail / 项目导航栏

目的：提供稳定的方向感。

内容：

- 产品标识和工作区状态
- 当前 `ResearchObject`
- 当前 `ResearchSession`
- 主 `ResearchThread`
- 资料数量
- 当前研究路径
- 主导航：
  - 研究地图
  - 候选结果
  - 资料
  - 关系图谱
  - 输出

行为：

- 固定窄栏
- 当前导航项有清晰但克制的选中态
- 不放长说明文案

### 2. Agent Run Feed / Agent 研究过程流

目的：让 Agent 的研究工作变得可见、可理解。

内容：

- 当前 Agent 阶段
- 第一层研究总结
- 关键发现
- marker 判断理由
- 推荐下一步动作
- 最近任务和任务状态
- 动作无法执行时的 warning

行为：

- 像研究日志，不像闲聊聊天记录
- 使用结构化块，例如“地图已生成”“发现风险”“建议下一步”
- 未来可以承接 streaming agent events

### 3. Research Map Canvas / 研究地图画布

目的：主研究 workflow 画布。

内容：

- 根研究节点
- 第一层子节点
- 节点状态
- marker badges：
  - focus
  - difficulty
  - risk
  - recommended drill-down
  - needs validation
  - uncertain
  - low priority
  - core entry
- 证据数量
- 动作数量
- 相关候选数量

行为：

- 默认模式是 `research_map`
- 选中节点必须非常明确
- 节点排列要像 workflow map，不像普通卡片网格
- 下钻只展开选中节点的一层
- 关系图谱可以切换查看，但它是次级视图

### 4. Node Inspector / 节点检查器

目的：让用户围绕选中节点采取行动。

内容：

- 选中节点标题、摘要、状态和 markers
- marker 判断理由
- 证据锚点
- 建议动作
- 旁路临时会话入口和会话列表
- 并行任务队列
- 候选结果及其 merge/review 状态
- 执行结果

行为：

- 空态应提示用户选择研究节点
- 只有选中节点具备下钻动作时，才突出显示“深入研究”
- 创建旁路会话不改变主研究地图
- candidate merge 必须显式触发
- 冲突候选显示为 `needs_review`

## 视觉方向

基调：工业化、克制、工具型研究驾驶舱。

这是一个反复使用的研究工具，不是落地页。

### 布局

- 全屏 app shell
- 不做 hero section
- 不做营销式构图
- 不做装饰性嵌套卡片
- 使用克制的面板边界
- 信息密度高，但保留可读间距
- 侧边区域固定宽度，中间画布自适应

### 色彩

- 背景：中性冷灰
- 主表面：近白色
- 次级表面：浅灰
- 文字：深石墨色
- 弱文字：灰绿色
- 强调色：深青绿色，用于当前选中和当前状态
- 风险：低饱和红
- 待验证：琥珀色
- 难点：靛蓝
- 候选/审核：灰紫

避免：

- 大面积紫蓝渐变
- 大面积米色、奶油色、沙色
- 装饰性光球、渐变球、背景泡泡
- 重阴影

### 字体

- 紧凑的工具型 UI 字体
- 小标题要清晰有力
- 正文清楚可读
- 面板内不使用 hero 级大字
- 元数据和标签应方便扫读

### 组件

核心组件族：

- rail item / 导航项
- agent event block / Agent 事件块
- node card / 节点卡片
- marker badge / marker 标签
- evidence row / 证据行
- action button / 动作按钮
- job row / 任务行
- candidate row / 候选结果行
- inspector section / 检查器分区
- canvas mode switch / 画布模式切换

卡片只能用于重复对象。页面大分区应该是 pane，不应该做成卡片套卡片。

## 核心工作流

### W1：建立方向感

用户进入后立即看到对象、会话、线程和第一层研究地图。

成功标准：

- 当前对象可见
- 当前地图模式可见
- 第一层节点可见
- 当前选中节点明确

### W2：选择研究路径

用户在地图上选择一个节点。

成功标准：

- 检查器内容更新
- 证据和动作更新
- marker 判断理由可见

### W3：深入研究

用户点击选中节点上的“深入研究”。

成功标准：

- 只展开该节点
- 不展开无关分支
- 重复下钻保持幂等

### W4：旁路提问

用户从选中节点创建旁路临时会话。

成功标准：

- 旁路会话出现在检查器中
- 主地图 nodes 和 edges 不变
- 沉淀或提升仍然需要显式动作

### W5：审核候选结果

用户审核并行分析输出。

成功标准：

- candidates 与主地图分离
- pending candidate 可以被合并
- 冲突 candidate 显示 `needs_review`

### W6：切换关系图谱

用户从研究地图切换到关系图谱。

成功标准：

- 关系图谱被明确表达为投影
- 它看起来不是可直接编辑的主数据源
- 返回研究地图的入口明确

## 实施边界

这次 UX pass 只改变前端结构和视觉呈现。

保留：

- 现有 research domain model
- 确定性 fixtures
- 确定性 research agent
- relationship projection
- 状态行为测试
- browser-local mode

本次不新增：

- 真实 PDF 渲染
- 真实 LLM 集成
- 真实文件索引
- 复杂图布局引擎
- 持久化
- 登录认证
- 超出辅助动作范围的导出流程

## 必需测试覆盖

新增或更新前端测试，断言：

- cockpit 四区能渲染：项目导航栏、Agent 研究过程流、研究画布、节点检查器
- 第一屏显示当前对象、会话、线程和路径
- 地图节点显示 marker badges 和元数据数量
- 选中节点会更新检查器内容
- 下钻只展开选中节点
- 旁路会话默认隔离
- 候选结果在 merge 前与主地图分离
- 关系图谱是可访问的次级模式
- 空态、warning、running job、conflict 状态都可见

## 浏览器验证清单

实现后必须：

- 在 Browser/IAB 中打开本地 app
- 验证桌面视口
- 验证窄视口
- 点击节点
- 下钻一次
- 切换到关系图谱并返回
- 确认 console 没有错误
- 对照本 spec 检查可见结果：
  - cockpit 四区
  - 信息密度
  - 字体层级
  - marker 可见性
  - 选中节点清晰度
  - 检查器可用性
  - 不再像营销页或 demo dashboard

## 验收标准

UX 重构可接受的条件：

- 第一屏看起来像研究驾驶舱
- 用户不读文档也能看出产品主循环
- 界面重心是研究 workflow map
- Agent 引导可见且可行动
- 证据和动作靠近选中节点
- 旁路会话和候选结果明显隔离
- 关系图谱被呈现为投影
- 测试和构建通过
- Browser/IAB 验证无 console error
